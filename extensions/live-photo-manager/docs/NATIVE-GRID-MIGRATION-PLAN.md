# Live Photo 原生网格迁移计划

## 产品契约

Live Photo 管家不提供第二套日常浏览器。Eagle 原生网格是唯一工作区：

```text
拖入/导入 Live Photo
  -> Eagle 里出现一个原生卡片
  -> 静态封面显示
  -> 悬停播放 MOV
  -> 原生选择、拖动、预览、文件夹和快捷键继续工作
  -> 右键追加导出静态图、MOV、Apple Photos 等动作
```

独立窗口只保留为诊断入口，用来查看配对冲突、台账和失败恢复。

## 已验证事实

- 真实样本 `IMG_4154.HEIC + IMG_4154.MOV` 可封装为一个 `IMG_4154.livp`；
- 通过 Eagle 本地 API 导入到 `livephoto 测试` 后，Eagle 原生网格显示一张卡片；
- Eagle 原生信息区显示格式 `LIVP`、尺寸 `4284 × 5712` 和可用缩略图；
- 这条路径没有打开 Live Photo 管家诊断窗口，也没有修改 Library 内部文件。

## 当前 API 边界（2026-11-06）

- Eagle 公开 Plugin API 没有原生网格 `contextmenu`、选中项右键或卡片悬停回调。
- `eagle.contextMenu.open()` 只能由插件自己已经收到的事件调用，不能把菜单注入 Eagle
  主窗口的原生卡片右键事件。
- 当前 `bridge/rebuild-native-bridge.js` 通过修改 `app.asar` 的 `app.bundle.js`、后台脚本和
  插件 IPC 来实现右键/悬停，这条路径属于宿主改包，不能作为正式安装方案；它会触发 Eagle
  完整性保护并违反宿主隔离门禁。
- 因此，在不修改 Eagle 宿主的前提下，`.livp` 原生卡片只能保留 Eagle 的静态封面和空格预览；
  原生网格右键追加导出动作暂时不能宣称可用。

### 原生拖出边界

Eagle 公开 API 也没有原生网格拖出事件或拖拽 payload 改写接口。用户从卡片直接拖出时，
宿主会按原生 item 路径发送 `IMG_4154.livp`；插件无法在拖动过程中把它替换成封面
HEIC/JPG。任何通过 `app.asar`、主窗口 DOM 或系统级鼠标钩子改写拖出内容的方案都属于
宿主改包，不能安装。

静态照片需要作为文件交给其他应用时，当前安全入口是“在其它应用打开”处理器或显式的
“导出静态照片”动作；这两条路径都会把封面解出到 Eagle Library 外，并保留原 MOV 与
`.livp` 卡片不变。

安全替代方案是：在插件诊断入口中对当前选中的 `.livp` 提供静态图、MOV 和完整 `.livp`
导出；如果未来 Eagle 提供原生网格右键回调，再将同一套 `native-live-registry` 导出服务接入，
不改变台账和原生网格所有权。

## 下一条实现链

1. **单写入导入器**：从已配对的 HEIC/JPG + MOV 生成 `.livp`，通过 Eagle 公开 API
   逐项导入当前文件夹，记录 `accepted -> confirmed`；
2. **原生右键桥接（待公开 API）**：等 Eagle 提供原生网格右键回调后，仅对 `.livp` 增加导出动作；
   在此之前不修改宿主，导出从诊断入口完成；
3. **原生预览适配**：让 Eagle 的 preview/thumbnail adapter 使用 HEIC 转 JPG 的临时
   缩略图，并把 MOV 作为悬停播放源；源文件保持只读；
4. **恢复与验证**：逐项确认缩略图、卡片可读回、重启后台账可恢复，再逐级测试
   `1 -> 3 -> 10 -> 50`。

## 约束

- 不在主网格注入第二套卡片，不覆盖 Eagle 原生 DOM 事件；
- 未确认的导入只记录为 `accepted`，不能显示为完成；
- 不直接修改 `.library` 内部文件；
- `app.asar` 只允许使用已备份、可重建、带指纹的最小桥接补丁；
- 诊断窗口不得成为用户必须打开的操作入口。
