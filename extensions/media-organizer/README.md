# Eagle 媒体智能整理

为 Eagle 4 提供确定性单级/多级排序、手动拖动、自动编号，以及完全离线的
图片与视频自动地域标签。

排序功能的唯一规范见 `docs/SORTING-RULES.md`，已发生故障的永久发布门禁见
`docs/PERMANENT-REGRESSION-CONTRACT.md`。本 README 只提供入口说明；出现冲突时
必须修正 README，不得建立第二套排序语义。

## 界面优先级

插件面板严格按以下层级呈现，三个高层开关不依赖当前排列方式：

1. **高层开关**：一个简洁框内只显示排序锁定、手动拖动、自动编号；每行各有自己的“应用到全部”。
2. **排列方式**：Eagle 原生排列方式，以及两个并列的插件方式：`拍摄时间排序`（单一拍摄时间键）和 `多级排序`（可自由组合多个键）。
3. **多级排序规则**：选择 `多级排序` 时直接在下方内联展开，可随时编辑排序键、方向和优先级。
4. **应用到全部**：位于排列层，用于把当前排列方式、升降序和多级规则复制到当前文件夹及全部子文件夹；保护层仍接收配置，但拒绝实际改变顺序。

`拍摄时间排序`和`多级排序`是两个独立的排列方式；不能再使用“多级拍摄时间排序”
这样的混合名称。旧状态键 `PHOTO_TAKEN` 继续兼容为多级排序，新单一拍摄时间入口
使用独立键，不影响已有规则迁移。

当前 GitHub 源码候选：`2.5.22-qa.94 / API150`。GitHub 干净插件包由
`scripts/build-github-release.sh` 在本机可重现构建为
`releases/媒体智能整理-v2.5.22-qa.94-github.eagleplugin`；发布包及其 SHA-256
校验文件是本机生成物，不提交团队状态、缓存、备份、恢复资料或真实 Library 数据。
包内不含团队状态、缓存、备份、恢复资料、Library 路径、测试库、Eagle `app.asar`
或桥接载荷；配套检查器默认只检查现有宿主和通信桥，不修改 Eagle。

GitHub 源码和插件包需要配合本机 Eagle 4.0.0 专用通信桥才能实现 1:1 原生排序。qa.94
的普通/智能文件夹排序、手动顺序、设置面板和团队 sidecar 投影都依赖这两个固定桥接
入口。目标电脑不需要复制第三方 `app.asar`：先运行 `bridge/rebuild-compatible-bridge.js`
在本机原始宿主上通过精确指纹检查并重建桥接，再安装插件。没有桥或宿主未知时安装器会
拒绝，而不是伪装成完整安装成功。

媒体层和父层拖动都进入同一条“完整最终顺序 -> 持久化 -> 原生网格”业务链。
父层显示直接子文件夹时只读取`currentFolder.children`，不能把全库媒体数组当成文件夹卡片。
当前层开关不自动递归；只有该行右侧`应用到全部`才同步全部后代。
显示简介属于纯展示状态，批量同步可写到当前文件夹及全部深层后代，包括受保护
文件夹。排序锁定会拦截新的排列、手动顺序和真实文件名修改；批量配置仍可同步到
保护层，但保护层不执行实际变更。批量状态
一次持久化，写入失败会回滚
本次内存改动；结果固定显示在发起操作的文件夹，不能串到其它父目录。

“全部”视图不提供文件夹级操作，插件桥接固定返回空素材列表，禁止每秒指纹、复制
和传输整库约 2.4 万条素材。NAS 冷启动仍需由 Eagle 枚举 Library 的 `images`
单目录；该目录当前约有 2.4 万子目录，SMB 首次枚举可能耗时较长，这是 NAS 元数据
瓶颈，不能通过排序插件轮询解决。

## 全局自动地域标签

- 从 Eagle 插件菜单打开“媒体智能整理”，即可进入地域标签设置页。
- “全局自动地域标签”默认开启。第一次启用时只建立当前资源库基线，不会突然
  扫描并改写全部历史项目；以后新导入的图片和视频会在后台自动处理。
- “扫描当前文件夹的拍摄地点”会递归处理 Eagle 主窗口当前文件夹及全部子文件夹，
  并按地点显示本次分布；例如同一个父文件夹可以同时显示 `沙特阿拉伯` 和
  `阿联酋`，点击任一地点可在多列缩略图中快速审核具体媒体。
- 当前文件夹扫描先预览，不立即写入新识别出的标签。结果正确时点击“确认并添加
  自动标签”，即可一次写入全部待确认结果，不需要重新输入软件已经识别出的地点。
- 已识别地点、“没有 GPS”和“未能识别”共用同一审核区。支持逐张选择、Shift
  连续选择、全选和取消选择，不会跳离当前 Eagle 文件夹。
- 对没有自动结果的媒体，可以批量补充地点；对识别错误的媒体，可以批量替换为
  正确地点。替换只移除原地域标签，人物、分类等其他标签保持不变。
- 手动补充或纠正的地点会写入处理记录，以后重新扫描时继续以人工结果为准。
- “整个图库的自动识别进度”只用于处理启用本功能前已经存在、但尚未识别地点的
  图库项目；它是次要的全库维护入口，不影响日常按文件夹扫描。
- “重新检查未识别文件”只重试坐标未匹配、元数据读取失败或标签写入失败的项目，
  不重复读取已经确认没有 GPS 的媒体。
- 中国大陆坐标写入简洁城市名，例如 `杭州`、`成都`；北京、上海、天津、重庆
  直接使用城市名；香港、澳门、台湾分别使用 `香港`、`澳门`、`台湾`。
- 国外坐标写入简洁国家名，例如 `日本`、`法国`、`美国`。
- 若 Eagle 已有完全同名的地域标签，插件直接复用；项目已有任一已知地域标签时，
  不再读取媒体 GPS，也不重复添加。
- 每个项目的处理结果按资源库保存。已经处理过的项目不会反复扫描；用户手动删除
  或修改地域标签后，后台增量扫描不会把旧标签重新加回。
- “没有 GPS”和“未能识别”是插件窗口内的临时审核分类，不会创建真实 Eagle
  文件夹。每次扫描当前文件夹都会替换上一次结果，只显示本次扫描范围。
- 图片通过 EXIF GPS 读取位置；视频读取 QuickTime/ffprobe 位置字段。整个识别过程
  完全离线，不调用地图 API、AI 或 token，也不会上传媒体或坐标。
- 行政区划数据来源与许可见 `data/ATTRIBUTION.md`。

## 文件夹统一地点标签

- 在“媒体智能整理”窗口的“给整个文件夹统一添加一个地点”区域输入 `杭州`、
  `日本` 等标签。
- 作用范围是 Eagle 主窗口当前打开的普通文件夹，以及它下面的全部子文件夹。
- 插件窗口保持打开时，在 Eagle 左侧切换文件夹会自动同步作用范围并重新统计，
  不需要关闭窗口，也不需要额外点击预览按钮。
- 页面会直接显示文件夹数、图片和视频数、已有同名标签数，以及本次真正需要
  添加的数量；更改标签后，后两项会立即在内存中重新计算。
- 只有点击带有明确文件数量和标签名的蓝色应用按钮，才会开始写入。
- 只处理图片和视频；同一项目属于多个目标文件夹时只处理一次。
- 已有同名标签的媒体不会重复写入，其他全部原有标签都会保留。
- 输入框会复用 Eagle 已有的同名标签，也可以输入一个新的简洁地点名。

## 文件名与 1-/2- 前缀分组

1. 文件名键的前缀分组选项：把 `1-人物...`、`2-环境...` 等内容分组。
2. 拍摄时间：在同一文件名前缀组内按 EXIF 或视频创建时间排列。

每个键分别选择升降序。普通文件名排序使用数字感知自然顺序；前缀预设只是
同一文件名键的解析选项，组内由后续键决定。

“应用 1-/2- 分组预设”和“恢复默认”都只生成以上两级。需要继续细分时，
可手动“添加一级”，例如再加入完整文件名或文件类型。

规则面板最多可配置 8 级，每一级都可独立选择升序或降序，并可调整优先级。
可用字段包括文件名、拍摄时间、媒体类型、扩展名、
添加日期、修改日期、创建日期、文件大小、分辨率、星级和时长。

## 显示相机拍摄时间

- 在“显示简介”的下拉菜单中可选择“相机拍摄时间”。
- 该显示项独立于排序方式，按名称、添加日期等方式排序时也可使用。
- 图片和视频显示为 `年/月/日 时:分`；没有可用拍摄时间及其他文件显示 `—`。
- 显示功能复用拍摄时间缓存，不修改媒体文件或 Eagle 资源库元数据。
- 每个文件夹分别保存自己的简介字段；在父文件夹可执行“应用到全部”，
  将当前简介字段一次性复制到当前文件夹及全部子文件夹。
- 批量应用是一次性复制。之后在某个子文件夹切换为修改日期等字段时，
  只覆盖该子文件夹，其他已设置文件夹保持不变。

## 文件夹级批量应用

“排序锁定”“手动拖动”“自动编号”是集合级高层行为，始终位于 Eagle
排列方式之上，不依赖当前选择原生、拍摄时间排序还是多级排序。只有多级规则编辑区
随“多级排序”方式显隐。

- 每个普通文件夹和智能文件夹分别保存自己的多级排序规则。
- 在有子文件夹的当前文件夹中，可对当前排列方式执行“应用到全部”。
- 操作会一次性复制当前排列方式和升降序；如果当前是“多级排序”，
  还会复制当前多级规则。
- 覆盖范围包括标题、尺寸、添加日期、修改日期等 Eagle 内置排列选项，
  以及插件新增的拍摄时间排序和多级排序。
- 递归目标会一直收集到最深层子文件夹；空文件夹也会同步设置。
- 若资源库路径暂不可用、NAS Library 离线、文件夹无效或部分写入失败，
  界面会显示失败或部分失败，不会静默报全成功；若有保护范围被跳过，
  结果会显示跳过数量和文件夹名称。
- 这不是持续继承。以后在某个子文件夹中选择其他排列方式或编辑规则，
  只覆盖该子文件夹，其他已经批量设置的文件夹保持不变。
- 再次从父文件夹批量应用时，才会重新覆盖它下面的规则副本。
- 智能文件夹的“应用到全部”明确只作用于当前智能视图，不改写来源普通文件夹。

## 团队排序状态接力

- 插件默认显示“团队同步：自动”；本机排序状态变化会 debounce 后自动写回，不要求用户发布。
- 诊断区仍提供“强制同步”“导出状态文件”“导入状态文件”，仅用于冲突处理和恢复。
- 自动同步会在 `.library` 旁创建同名 sidecar，例如
  `引力环球.library.eagle-team-state.json`；不会进入或手工修改 `.library` 内部。
- 其他电脑安装同版本插件并打开同一个 Library 时，会优先读取该 sidecar，恢复
  排序规则、防止全局覆盖、集合手动视图、简介/显示类型、升降序和 Library 级排列键。
- 自动读取还要求 qa.94 主窗口通信桥已通过精确宿主指纹检查；sidecar 本身不能替代
  桥。无桥时状态文件仍保持原样，但不会投影为 Eagle 主网格中的 1:1 排序。
- 状态文件包含 payload SHA-256、发布插件版本和全部文件夹 ID 指纹。自动读取前
  必须通过完整性校验，并要求至少 80% 的源文件夹 ID 能在当前 Library 中找到；
  不能仅按文件夹名称猜测导入。
- Library 后续新增文件夹不会阻止读取；被删除或失效的旧文件夹会在兼容性结果中
  列为缺失，错误 Library 会被拒绝。
- 自动编号开关会进入状态文件，保证交接包完整，但接收电脑不会自动启用它，避免
  一打开 Library 就修改真实文件名；需要成员在目标文件夹中再次明确勾选和开始。
- 导入只写插件自己的 Local Storage 状态，不复制 Chromium LevelDB，不批量改
  媒体文件；每个 Library 和 payload 只导入一次，重复打开保持幂等。
- 覆盖前备份仍保存在 `eagle.photoTakenSort.teamImportBackup.v1`；覆盖已有 sidecar
  前会把旧文件复制到插件目录的 `team-state-backups/`。
- sidecar 写入携带 `revision`、`updatedAt`、`writerId`；写入使用原子替换、lock 文件和
  mtime/大小/内容指纹检测。发现其他电脑已更新时拒绝静默覆盖并停止本机自动写入，直到重新读取。
- 历史 `defaults/sort-state/team.eagle-sort-state.json` 仅作为 2.4.5-2.4.7 的首次
  迁移兜底。正式团队协作以 Library 旁的 v2 sidecar 为准。

完整交付流程与文件清单见 `docs/team-state-portability.md`。

## 手动拖动

- 当前层显示媒体时，可把当前选中的一张或多张媒体拖到目标项前后。
- 当前层显示直接子文件夹时，拖动对象改为子文件夹；多层后代不会混在一次拖动中。
- 手动拖动模式按集合保存，普通文件夹和智能文件夹相互隔离。
- 只有明确拖动才保存 `manualViews.v2`；刷新、改简介、自动编号和重新打开集合
  都不会隐式捕获当前可见顺序。
- 关闭手动拖动只停止新的拖动输入，已保存顺序、名称和画面保持不变；只有用户明确点击“恢复规则顺序/重置顺序”才清除手动顺序。
- 不写入 Eagle 项目的 `order` 字段，不切换到 Eagle 的永久“手动排序”。
- 设置面板提供撤销上次拖动和恢复规则顺序。
- 适合先临时调换照片，再按当前显示顺序执行连续重命名。

## 排序锁定

- 排序锁定是最高优先级硬锁。开启后，当前集合不能修改排列方式、多级规则、
  手动顺序，也不能执行媒体或子文件夹编号；唯一恢复入口是关闭锁定。
- 当前层开关只锁当前容器；右侧`应用到全部`才递归锁定或解锁全部后代。
- 硬锁保存在`sortingLocks.v3`。旧`protection.v2`的17个团队保护会自动升级为
  可见硬锁；现有新锁不覆盖，旧809条项目顺序不迁移。
- 锁定状态不保存可见顺序，`manualViews.v2`仍只保存真实拖动产生的媒体视图顺序。

### 状态迁移与回滚

- schema v3 排序规则和比较器保持不变；`manualViews.v2`继续只承载显式手动顺序。
- `protection.v2`保留旧17个保护和809条已忽略顺序的诊断；2.5.21 将保护合入
  `sortingLocks.v3`，用户明确解除后以抑制标记避免重启复活。
- 新硬锁写入`sortingLocks.v3`，每集合手动拖动开关写入`manualMode.v1`。回滚到2.5.8
  时旧版会忽略这两个新键，原`protection.v2`和`manualViews.v2`仍可读取。
- 本机2.5.12安装前完整备份位于
  `/Users/max/Library/Application Support/Eagle/Backups/media-organizer-plugin-before-2.5.12-20260722-205900`；
  恢复插件目录即可回滚运行代码，新键可保留为惰性数据，不需要修改`.library`。

## 自动编号

- 当前层显示直接子文件夹时，按可见顺序生成`1-名称`、`2-名称`；会解析全/半角
  数字、空格和多种连接符，并先显示逐项预览。
- 当前层显示媒体时，先计算当前单级/多级排序和显式手动拖动的最终
  可见顺序，再按该顺序连续编号；不使用 Eagle 原始 `raw` 顺序。
- 叶子层只处理当前普通文件夹中以`1-`或`2-`开头的图片和视频；其他文件保持不变。
- 文件夹名会作为场景名。若文件夹名为 `22-海上甬定`，会去掉开头编号，
  生成 `1-海上甬定1`、`1-海上甬定2` 和 `2-海上甬定1` 等名称。
- 人物组 `1-` 与环境组 `2-` 分别按照当前显示顺序从 1 连续编号。
- “预览并重命名”可以执行一次；开启“自动连续重编号”前也必须先确认预览。
- 自动开关按文件夹分别保存且默认关闭。开启后，只有明确有效的手动放置会自动按
  最新完整顺序编号；删除、导入、刷新、切换、启动和列表补全都不会自行触发改名。
- 重命名同时更新 Eagle 名称和实际文件名；面板可撤销最近一次重命名，撤销时
  会自动关闭连续重编号，避免刚恢复的名称被再次覆盖。
- 智能文件夹不能静默开启自动改名；执行前必须查看逐项预览，界面会提示受影响的
  来源文件夹数量。智能视图中的手动顺序不会写入来源文件夹视图。

## 递归自动编号

- 在父文件夹的“自动编号”区域可执行“应用到全部”。
- 勾选“自动编号”只处理当前层直接对象；存在子文件夹时，必须另点该行右侧
  “应用到全部”并确认，才会把开关递归下发到后代并启动获准的批量处理。
- 操作先为整棵树同步自动编号状态；真实重命名必须另有明确范围、预览和确认，
  不会覆盖各子文件夹已有的多级排序规则，保护层只同步状态、不执行重命名。
- 大批量任务会显示读取文件夹和同步文件名的实时数量及百分比；编号不等待拍摄时间。
  单个文件超时会记录为失败并继续处理，不会让整个批次永久停住。
- 每个文件夹独立提取自己的场景名并分别计算 `1-` 人物组与 `2-` 环境组，
  不会把不同子文件夹合并成一组编号。
- 同一 Eagle 项目同时属于多个目标文件夹时会作为共享冲突跳过，避免被不同
  场景名反复覆盖。
- 每次树级批量执行前，最近一次名称映射会保存到插件运行目录的
  `rename-batch-backup.json`。
- 批量应用后，任意子文件夹仍可单独关闭自动重编号；其他文件夹不受影响。

## 拍摄时间

- 图片优先读取 EXIF 的 `DateTimeOriginal`，其次使用
  `DateCreated`、`CreateDate`、`ModifyDate`。
- 视频读取容器或视频流的 `creation_time` 等拍摄时间字段。
- 没有拍摄时间的项目会排在同级有效值之后，再继续比较后续规则。
- 只扫描当前文件夹或当前筛选结果，不会在每次点击时扫描整个资源库。
- 解析结果缓存在插件目录，不修改图片、视频和 Eagle 资源库元数据。

## 兼容性

当前实现针对 Eagle 4.0 build 23。它通过后台插件连接 Eagle 主窗口，
因此 Eagle 大版本更新后可能需要同步更新界面注入逻辑。

为把选项真正加入 Eagle 的原生“排列方式”，当前已审计电脑预先存在一个只接受
本插件标记请求的专用通信桥。公开插件 API 没有等价的主网格排序注入、原生拖动反馈
或主窗口 DOM 通道。

GitHub 发行只包含插件和默认只读检查器。运行
`releases/install-媒体智能整理-v2.5.22-qa.94.sh --check` 会核对 Eagle 版本、
`app.asar` 精确哈希、插件身份、包 SHA-256 和同 ID 来源数；无桥、未知桥或多来源一律
拒绝。检查器没有安装桥的参数，也不会写入 Eagle host。只有宿主已经满足审计前提时，
才可在 Eagle 完全退出后显式安装插件。
