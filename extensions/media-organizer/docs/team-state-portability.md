# Eagle 团队排序与展示状态接力

## 目标

主整理电脑完成整个 Eagle Library 的精排后，把 Library、媒体智能整理插件和团队
状态交给其他成员。成员在另一台电脑打开同一份 Library 时，应看到相同的排序规则、
升降序、配置保护、集合手动视图、显示简介和多级排序规则。

## 正式方案

2.4.8 起，团队母版保存在 Library 同级文件：

```text
引力环球.library
引力环球.library.eagle-team-state.json
媒体智能整理-v2.4.8.eagleplugin
```

sidecar 不在 `.library` 目录内部。插件不会直接编辑 Eagle 私有数据库、metadata 或
其他内部文件。

## 自动同步电脑

1. 在每台团队电脑安装同一候选插件并打开同一 NAS Library。
2. 插件启动或切换 Library 时自动读取同级 sidecar，完成兼容性和 SHA-256 校验后导入本机状态。
3. 本机手动顺序、排序规则、排序锁定或手动拖动开关发生真正变化后，插件 debounce 后自动写回同级 sidecar；日常不需要点击“发布团队状态”。
4. “强制同步（诊断）”仅保留为显式诊断入口；导出/导入按钮也只用于诊断和恢复。

自动写入使用原子临时文件替换、同级 lock 文件和 sidecar mtime/大小/内容指纹检测；写入前备份保存在稳定 PluginData 根的 `team-state-backups/`，不再写入会被安装替换的插件代码目录。

## 团队成员电脑

1. 先确认 Eagle 4.0.0 宿主已经具有 qa.26 审计通过的专用通信桥；GitHub 插件包和
   检查器不会安装、替换或修改 `app.asar`。
2. 安装不低于发布状态中记录版本的“媒体智能整理”。
3. 打开同一座 NAS Library，或打开连同 sidecar 一起复制的 Library。
4. 插件校验 SHA-256 和文件夹 ID，相容后自动导入本机 Local Storage。
5. 同一 payload 重复打开不会重复覆盖。

sidecar 只携带插件状态，不提供主窗口执行通道。没有通信桥时，插件无法把普通/智能
规则、手动关系和显示状态投影到 Eagle 原生网格，因此不能达到 1:1 排序；它会放行
Eagle 原生结果，不修改 sidecar。团队状态文件不得打入 GitHub 插件包。

若 sidecar 没有和 Library 放在一起，可打开插件窗口，使用诊断“导入状态文件”手动选择。

## 覆盖范围

- Eagle 当前 Library 的排列方式与升降序回退键。
- 普通文件夹和智能文件夹的多级排序规则。
- `protection.v2` 中的“防止全局覆盖”开关、锁定时间和完整排序配置。
- `manualViews.v2` 中由明确拖动产生的集合专属项目 ID 顺序。
- 每个文件夹的简介/显示类型，以及全局显示类型。
- 临时自由拖动是否启用等非破坏性排序偏好。
- 自动编号开关会进入状态文件，但不会在接收电脑自动启用。

## 2.5.0 迁移说明

- 旧 `folderLocks.v1` 继续作为只读兼容输入。17 个保护条目迁成配置保护。
- 旧保护条目中的 809 个项目 ID 不会导入 `manualViews.v2`，只保留忽略诊断。
- 新 sidecar 发布会同时包含 `protection.v2` 和 `manualViews.v2`；两者按 Library、
  普通文件夹和智能文件夹分别重映射。
- 回滚到 2.4.8 前先备份已安装插件目录和 sidecar。2.5.0 不删除旧 key，因此旧版
  仍可读取旧交接状态；禁止把忽略诊断人工改回项目顺序。

Eagle 自己保存在 Library 内的原生文件夹字段仍由 Eagle 随 Library 携带；sidecar
负责补齐插件 Local Storage 中无法随 Library 自然迁移的部分。

## 校验与失败

- payload SHA-256 不一致：拒绝导入。
- schema 不支持：拒绝导入。
- 文件夹 ID 命中率低于 80%：视为错误 Library，拒绝自动导入。
- Library 新增文件夹：允许导入，新增文件夹保持本机默认，直到下次发布。
- 源状态包含已删除文件夹：导入现有项并报告缺失，不按名称猜测替代。
- NAS 离线、目录只读或路径失效：发布失败并保留现有 sidecar，不显示成功。
- 重复发布：生成新 payload；重复导入同一 payload 保持幂等。
- 两台电脑并发变化时采用“拒绝静默覆盖”：若 sidecar 自本机上次读取后发生变化，当前电脑停止自动写入并显示冲突；重新读取或切换 Library 后才恢复同步。
- NAS 离线、权限不足、锁竞争或原子替换失败时保留旧 sidecar 和本地状态，显示错误，不自动改名、不自动启用自动编号。

## 交付检查清单

- `.library` 与 `.eagle-team-state.json` 基名一致并位于同一父目录。
- 插件版本不低于状态中记录的版本。
- 接收电脑页面显示 Library ID 相容校验通过。
- 抽查标题/尺寸/名称/拍摄时间排列、升降序和显示简介。
- 抽查已保护文件夹仍显示“防止全局覆盖”，且上级“应用到全部”会跳过。
- 自动编号在接收电脑保持未自动启用。
