# 网页媒体保存至 Eagle

这是一个独立 Chrome 扩展。用户点击扩展按钮，或在网页/图片/视频上打开右键菜单后，
它收集**当前页面已经加载且具有直接 HTTP(S) 文件地址**的图片和视频，让用户选择一个
普通 Eagle 文件夹，再逐项下载并通过 Eagle 公开本地 API `addFromPath` 交给 Eagle。

## 当前能力

- 保存当前网页中已经加载的直连图片和直连视频；也可以只保存右键选中的一项媒体。
- 在导入前列出 Eagle 普通文件夹，由用户明确选择；智能文件夹不会作为写入目标。
- 同一批次按页面可见顺序去重，最多处理 80 项，逐项串行下载和提交，避免同时压满网络与 Eagle。
- 来源网页、原始媒体地址、来源站点和媒体类型写入 Eagle 项目来源、标签与简介计划；常见签名、
  token、账号凭证和追踪参数会先从共享来源文字中移除。
- 最近 20 个批次保存在扩展本地存储中；失败项保留原因，可在扩展弹窗中重试。
- Chrome 下载缓存只在 Eagle 公开 API 返回 `success`（代表“已接收请求”）后安排清理，并保留至少
  24 小时，避免 Eagle/NAS 较慢时过早删除源文件。

## 明确不支持

这不是“任意网站万能下载器”。下列地址会明确跳过，不会伪报保存成功：

- `blob:` 浏览器临时对象、`data:` 内嵌数据；
- HLS/DASH 分片清单（`.m3u8`、`.mpd`）；
- DRM/加密/受保护视频、需要绕过登录或站点权限的内容；
- 页面尚未加载、没有暴露直接文件地址的媒体；
- 创作者主页批量爬取、自动翻页或后台采集。

Instagram 单帖轮播和小红书单帖的站点专用能力仍由各自扩展维护。本扩展只提供通用的
“当前网页直连媒体”入口，不承诺覆盖每次站点改版或所有视频播放形式。

## 安装前验证

```bash
cd extensions/web-media-importer
npm test
npm run check
npm run package:stable
```

打包结果位于仓库根目录 `releases/网页媒体保存至Eagle-Stable/`（该目录不提交 Git）。
可从源码目录加载，也可以加载打包目录中的 `eagle-web-media-importer`：

1. 在 Chrome 打开 `chrome://extensions/`。
2. 开启「开发者模式」，点击「加载已解压的扩展程序」。
3. 选择本目录或上面的干净打包目录。
4. 已经打开的网页无需手动刷新：点击扩展按钮时，后台会在允许的普通网页中补注入采集器。

## 使用

1. 打开 Eagle 和目标资源库。
2. 打开你有权保存的普通网页。
3. 点击扩展按钮的「保存当前页面媒体」，或右键选择保存本页/当前媒体。
4. 在网页内弹出的选择器中选择普通 Eagle 文件夹。
5. 在扩展弹窗查看“Eagle 已接收”和失败数量；失败项可以重试。

“Eagle 已接收”仅表示公开 API 已接受本地路径，不替代 Eagle 界面的最终可见验收。扩展不读取、
修改或扫描 `.library`，不修改 `app.asar`，也不直接操作 NAS 素材。

## 发布包边界

稳定包只包含 `manifest.json`、四个运行脚本、弹窗页面和本 README；测试、项目台账、本机队列、
下载缓存、Library/NAS 路径和任何账号/密钥均不进入发布包。
