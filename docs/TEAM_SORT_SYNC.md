# 团队排序同步

## 用户看到的交互

1. 主电脑在普通文件夹或智能文件夹选择插件排序规则，或进行手动拖动。
2. 插件在状态稳定后自动把插件自己的排序状态写到 Library 旁的同名 sidecar。
3. 团队成员安装同版本插件并打开同一个 NAS Library。
4. 插件自动校验 sidecar 的格式、SHA-256 和文件夹 ID 匹配度，然后恢复规则与手动相对顺序。
5. 成员无需点击“发布团队状态”，也无需重新排序。

sidecar 示例：

```text
项目.library
项目.library.eagle-team-state.json
```

它位于 `.library` 外部，不修改 Eagle Library 内部结构。

## 同步内容

- 普通文件夹排序规则；
- 智能文件夹排序规则；
- 普通/智能文件夹的手动相对顺序；
- 排序锁定与手动模式；
- 简介显示字段和升降序；
- 自动编号配置（仅状态携带，不在接收电脑自动执行真实改名）。

## 冲突保护

- 写入使用临时文件加原子替换；
- 同级 lock 防止并发写；
- revision、writerId、mtime、大小和内容指纹用于检测另一台电脑已更新；
- 发现冲突时停止自动覆盖，要求重新读取，不采用“最后写入者无条件覆盖”；
- 错误 Library 或文件夹 ID 匹配不足会拒绝导入。

## 团队使用规则

- 可以多台电脑读取同一 Library，但同一时刻只建议一台电脑修改 Library 或团队排序状态；
- 另一台电脑正在导入或更新 Library 时，不要反复刷新；
- NAS 离线、sidecar 冲突或 Eagle 正在后台重算时，先停止写入并等待状态稳定；
- 不把 sidecar 放进 GitHub。它属于团队运行数据，不属于软件源码。
