# Eagle 排序系统总规则（唯一规范）

本文档是排序功能的唯一产品语义。代码、界面、测试和恢复流程全部必须服从本文档。
`PERMANENT-REGRESSION-CONTRACT.md` 只记录已发生故障的永久禁止回归项。

本文档描述必须实现和验收的目标行为，不等于当前安装版已经通过。实现、自动测试、
日志或历史决策与本文档冲突时，必须先按本文档修正；未完成真实 Eagle 界面验收前，
只能称为开发预检，不能称为可用或无 bug。

## 0. 规则层级总览

```text
L0 产品入口：只在 Eagle 原生照片网格和原生排列面板工作
L1 隔离边界：Library -> collection
L2 对象判断：父层直属子文件夹 / 叶子层直属素材，二选一
L3 作用范围：仅当前层 / 当前层及全部后代
L4 顺序计算：Eagle 原生基础 -> 插件自动规则 -> 明确手动顺序 -> 最终可见顺序
L5 结果动作：只调整显示顺序 / 按同一最终顺序预览并编号
L6 安全保护：锁定只拦截后续变更，开关本身零副作用
L7 持久化与执行：分库存储、原生安全改名、失败隔离和恢复
L8 验收：只认真实 Eagle 界面
```

### 0.1 术语

- **当前集合**：适配器明确识别出的一个普通文件夹或一个智能文件夹结果。
- **完整最终顺序**：当前集合全部目标对象的 item/folder ID 顺序，不是当前页、选中项或局部 DOM 片段。
- **已保存手动顺序**：用户有效放置后，按 Library ID + collection ID 保存的完整最终顺序。
- **手动拖动能力**：普通/智能 collection 默认具备；只有排序锁定或不可操作上下文禁止。
- **重置顺序**：用户明确放弃已保存手动顺序、恢复自动规则结果的唯一操作。
- **自动编号**：排序后的可选命名动作，不是另一套排序器。

### 0.2 唯一入口

- 用户直接看着 Eagle 原生照片卡片操作，不需要进入独立原型或第二套排序界面。
- 排序服务可随 Eagle 启动，但不得自动打开“媒体智能整理”标签/GPS 窗口。
- GPS、地点标签和其它媒体整理能力不属于排序链，不得因排序启动或拖动被初始化。

### 0.3 Eagle 原生功能不可侵犯

- 排序只是网格内部的局部能力，不拥有照片卡片的全部拖放权限。
- 从照片卡片拖向 Finder、桌面、聊天框、上传框、其它软件或 Eagle 其它原生目标时，必须完整保留 Eagle 原生拖放。
- 排序代码不得取消原生 `dragstart`，不得修改原生 `dataTransfer`，不得拦截网格外的 `dragover/drop`。
- 只有光标进入另一个有效网格卡片落点并在该处放手时，排序功能才获得本次 drop 的处理权。
- 拖出 Eagle 或放到非排序目标时，不得改变可见顺序、手动顺序、文件名、选择状态或原生导出文件。

## 1. 唯一用户结果

用户在 Eagle 原生照片网格看到什么顺序，系统就必须保存什么顺序。

用户完成手动拖动后：

1. 照片立即留在放置位置。
2. 当前完整顺序立即按 Library ID + collection ID 保存。
3. 已开启自动编号时，只按该可见顺序连续更新名称。
4. 刷新、切换文件夹、重启 Eagle 和开关排序锁定都不得改变已排顺序。

排序功能只允许下列业务链，不得存在第二条业务链：

```text
真实有效拖动
-> 读取当前集合完整最终顺序
-> 保存该顺序
-> 立即更新 Eagle 原生网格
-> 如已开启自动编号，按同一顺序生成改名计划
-> 通过 Eagle 原生改名管线安全落盘
-> 按已保存顺序确认最终界面
```

## 2. 作用层级

### 2.1 资源库层

- Library ID 是最高隔离边界。一个库的配置、手动顺序和保护状态不得污染另一个库。
- “全部”、“未分类”和未知上下文不是文件夹集合，排序、拖动和编号一律不可操作。
- 禁止为了判断当前集合而扫描整个资源库。

### 2.2 collection 层

- 普通文件夹和智能文件夹均以 collection ID 隔离。
- 两种适配器只转换为同一核心输入，不得各自实现排序规则。
- 智能文件夹只处理当前智能结果，不得回退整库。
- 手动顺序、批任务和进度必须按 collection ID 隔离。

### 2.3 当前层对象

- 当前文件夹有直属子文件夹时，处理对象只是直属子文件夹。
- 当前文件夹没有直属子文件夹时，处理对象只是该叶子文件夹的直属素材。
- 两种对象不得混用，后代素材不得冒充当前层直属素材。

### 2.4 作用范围

- “仅当前层”只处理当前层对象。
- “当前层及全部后代”显式遍历任意深度文件夹树，包含空层和保护层。
- 只有用户明确点击“应用到全部”才能进入后代范围。
- 保护层仍接收配置，但拒绝实际排序、拖动和改名。

### 2.5 对象与范围矩阵

| 当前上下文 | 当前层目标 | “仅当前层” | “应用到全部” |
| --- | --- | --- | --- |
| 有直属子文件夹的普通文件夹 | `direct-folders` | 只处理直属子文件夹 | 配置下发到当前文件夹及任意深度后代 |
| 无直属子文件夹的普通叶子文件夹 | `direct-media` | 只处理直属素材 | 无后代时不显示或禁用 |
| 智能文件夹 | 当前智能结果 | 只处理当前结果；手动顺序写入智能 collection 自身 | 不改写来源普通文件夹、不继承来源文件夹自动编号，也不虚构后代 |
| “全部”/未知上下文 | 无 | 受控不可操作 | 受控不可操作且处理 0 项 |

### 2.6 “应用到全部”的逐项语义

- **排列方式**：复制排列方式、方向和相关多级规则；保护层保存配置，但不立即改变其画面。
- **手动拖动**：是 collection 默认能力，不再提供开关或递归下发；批量操作不得复制、清除或重算手动顺序。
- **自动编号**：只复制自动编号状态；真实改名仍须由有效拖动或明确预览确认触发，保护层拒绝执行。
- **排序锁定**：只复制锁定状态；批量锁定或解锁本身仍然零排序、零刷新、零改名、零顺序捕获。
- 每项批量操作独立，不能顺带修改其它开关、排列规则、手动顺序或名称。
- 批量操作是一次性复制，不是永久继承；子文件夹以后可单独修改，直到用户再次批量应用。

## 3. 顺序优先级

从高到低的唯一优先级：

1. 排序锁定作为最高权限 guard，冻结当前最终顺序但不产生新顺序。
2. 用户明确拖动产生的已保存手动顺序。
3. 当前选择的插件自动排序规则。
4. Eagle 原生排序结果；插件关闭、失败或受控不可用时完整回退。
5. 确定性稳定后备次序（文件名、ID、原始位置）。

```text
适配器明确提供的当前集合
-> 纯自动排序结果
-> 已保存手动顺序覆盖
-> Eagle 原生网格最终可见顺序
-> 自动编号输入
```

已保存手动相对关系存在时，拍摄时间、文件名、Eagle 原始数组、DOM 插入顺序和旧完整
快照都无权删除该关系；自动规则仍先生成新的基础顺序，再应用关系。

### 3.1 唯一顺序公式

```text
自动基础顺序 = stableSort(适配器当前集合, 当前规则)
最终顺序 = applyManualOverlay(自动基础顺序, 已保存相对关系)
编号顺序 = 最终顺序
```

- 没有已保存手动顺序时，最终顺序等于自动基础顺序。
- 存在已保存手动关系时，切换或编辑自动规则会改变基础顺序，然后重新应用相对关系。
- 只有“恢复自动排序”能删除活动关系；恢复后立即显示当前自动规则结果。
- 当前集合新增项目时，新项目可按自动规则稳定补入；已有项目的手动相对次序保持不变。

### 3.2 冲突裁决

同一个事件如果同时匹配多条规则，按以下顺序裁决：

1. 先判断 collection 是否明确且可操作。
2. 再判断排序锁定是否拒绝该变更动作。
3. 再判断是否存在已保存手动顺序。
4. 再执行用户本次明确动作。
5. 最后才允许自动编号消费同一最终顺序。

任何定时器、刷新回调、成员监听器或历史兼容代码都没有更高权限。

## 4. 排列方式与自动排序规则

### 4.1 界面层级

Eagle 原生排列面板中的固定层级是：

1. 高层控制：排序锁定、手动拖动默认状态和自动编号；手动拖动没有开关。
2. 排列方式：Eagle 原生方式、拍摄时间排序、多级排序。
3. 多级规则：仅选择“多级排序”时在排列方式正下方展开。
4. 命令：撤销拖动、重置顺序、编号预览/确认只在对应上下文可操作时出现。

高层控制不隶属于某个排列方式。切换排列方式不得隐藏、重置或联动锁定与自动编号。

### 4.2 排列方式

- **文件名/其它 Eagle 原生方式**：使用 Eagle 当前基础排列结果，再由已保存手动顺序覆盖。
- **拍摄时间排序**：只有一个拍摄时间比较键；有无拍摄时间不影响任何其它能力。
- **多级排序**：按用户配置的键、方向和优先级依次比较，最多 8 级。
- **手动拖动**：不是清空自动规则的第四套引擎，而是所有基础排列结果之上的最高优先级覆盖层。

“拍摄时间排序”和“多级排序”是两个并列选项，不得再合并成含义不清的“多级拍摄时间排序”。

### 4.3 可选键

可使用文件名、拍摄时间、媒体类型、扩展名、导入时间、修改时间、创建时间、文件大小、分辨率、评分和时长等确定性比较键。

每一级独立选择升序或降序，并可调整优先级、增加或删除。文件名前缀分组是文件名键的解析选项，不是另一套排序引擎。

### 4.4 默认规则

1. 文件名前缀分组，`1-` 在 `2-` 之前。
2. 同组内按拍摄时间升序。
3. 缺失拍摄时间的素材稳定放在该比较键末尾。
4. 缺失拍摄时间只影响该自动键，不影响拖动、保存和编号。

### 4.5 确定性

- 中文、数字、全半角和不同连字符先统一正规化。
- 文件名自然排序使用数字感知比较，`2` 在 `10` 之前。
- 所有键相同时使用稳定后备次序，重复执行必须得到相同结果。
- 升降序只改当前规则方向，不得暗中改其它规则。

## 5. 手动拖动规则

### 5.1 默认能力

- 普通和智能 collection 默认允许新的网格内手动拖动。
- 不再提供“手动拖动”开关，也不再保存或递归下发启停状态。
- 排序锁定或不可操作上下文拒绝新的网格内拖动。
- 只有用户明确点击“恢复自动排序”才允许清除当前 collection 的手动顺序。

### 5.2 拖动资格

- 只有明确可操作的当前集合才能拖动；排序锁定时禁止。
- 有无拍摄时间、时间是否已读取都不得影响拖动。
- 智能文件夹中的素材同样可拖；Eagle 暂时残留的旧普通文件夹对象不得改变智能集合的
  `direct-media` 身份或拖动资格。
- 单击只选中；超过拖动阈值并在有效落点放手才算一次拖动。

### 5.3 唯一拖动状态机

- 只允许一条基于 Eagle 原生拖动会话的状态机处理网格内落点和放手。
- Eagle 原生 HTML5 `dragstart` 始终保留；排序只能观察来源，不能取消或取代原生文件拖出。
- 只有有效网格内 `dragover/drop` 由排序接管，网格外拖放始终由 Eagle 原生处理。
- 每次放置都在上一次已保存的完整顺序上计算。
- 快速连续拖动可合并尚未落盘的编号任务，但可见位置必须每次立即生效，最后只以最新手动顺序为准。

### 5.4 完整性

- 保存当前集合的完整 item ID 顺序，不保存“拖了几次”、当前页片段或 DOM 节点列表。
- 分页或虚拟渲染未呈现全部卡片时，必须以已保存完整顺序为基础，不得用当前屏幕片段覆盖整个集合。
- 新增项目可按当前自动规则稳定补入，已保存项目的相对手动顺序不得改变。

### 5.5 手动顺序生命周期

- **有效拖动**：立即生成并保存新的完整顺序，增加一条可撤销历史。
- **撤销拖动**：只回到本 collection 的上一个已保存顺序，不影响其它集合。
- **恢复自动排序**：明确清除当前 collection 的手动顺序与对应撤销历史，然后显示当前插件自动规则结果。
- **刷新/切换/重启**：读取并恢复已保存顺序，不创建新历史、不改名。

### 5.6 拖动后可见反馈

- 放手后位置必须立即固定，不等待拍摄时间、不等待 NAS 改名完成。
- 下一次拖动必须以上一次已经保存的结果为起点，不能回到最初数组重新计算。
- 自动编号关闭时，拖动只改变顺序和手动顺序存储，绝不改名。
- 自动编号开启时，先完成位置与顺序保存，再从同一顺序创建一个当前 collection 的编号任务。

## 6. 自动编号规则

### 6.1 唯一输入

自动编号只能消费当前集合的最终可见顺序。禁止重新按拍摄时间、原始数组、旧编号、旧快照或不完整 DOM 排序。

### 6.2 父层直属子文件夹编号

- 当前目标为 `direct-folders` 时，只按当前可见顺序编号直属子文件夹。
- 先移除已有全/半角数字和各种连接符组成的层级前缀，再生成 `1-名称`、`2-名称`、`3-名称`。
- 不处理孙级文件夹，也不把后代素材混入当前层。
- 必须先显示逐项预览；执行使用安全临时名和最终名两阶段计划。

### 6.3 叶子层直属素材命名

- 只处理名称以 `1-` 或 `2-` 开头的图片和视频。
- `1-` 和 `2-` 保留原分组，分别从 1 开始连续计数。
- 场景名从当前文件夹名去除层级数字前缀后得到。
- 最终名称为 `分组-场景名+连续序号`。
- 不符合分组前缀的项目只能明确忽略，不得隐式改名。

### 6.4 触发权限

只有两个事件允许创建编号任务：

1. 自动编号已开启时，用户完成一次明确有效的手动放置。
2. 用户查看编号预览后明确确认执行。

启动、锁定开关、手动开关、自动编号开关本身、拍摄时间读取、打开面板、切换文件夹、刷新、分页、滚动、列表补全和成员指纹变化都永远无权创建编号任务。

### 6.5 变更边界

- 改名计划只包含新名与当前名不同的项目。
- 移动一张照片跨过 N 个同组位置时，连续编号可能需更改该区间内 N+1 个名称，但不得改区间外或其它集合。
- 相邻两张互换时只应产生该两张的编号差异。
- 预览顺序、提交顺序和真实界面顺序必须逐项相同。

### 6.6 界面与落盘

- 放手后必须立即显示最终业务名，不得等待 NAS 落盘才反馈。
- 真实文件改名必须通过 Eagle 原生 `ayncsImagesChange`；禁止直接批量写 `.library` 或使用 `item.save()` 冒充文件改名。
- 落盘使用“安全临时名 -> 最终名”两阶段事务解决循环换名冲突。
- `__eagle_number` 内部临时名永远不得出现在网格或右侧检查器。
- 同一时刻只能有一个编号任务；快速拖动只保留最新顺序待续行。
- 当前 collection 进度不得串到其它文件夹。

### 6.7 树级编号

- 父层的“应用到全部”先把自动编号状态下发到当前文件夹及全部后代。
- 真正执行前必须给出明确范围和逐文件夹预览/确认；不得仅因状态同步就后台改名。
- 每个叶子文件夹使用自己的场景名、自己的最终顺序，并分别计算人物组与环境组。
- 同一素材同时属于多个目标文件夹、成员发生变化或范围无法唯一确认时，必须跳过并报告冲突。
- 保护文件夹保留同步后的配置，但拒绝实际改名；未保护的其它文件夹可继续处理。

## 7. 排序锁定规则

排序锁定只冻结当下已呈现的版面和文件名。

- 开启或关闭锁定本身必须零排序、零刷新、零改名、零手动顺序重捕获。
- 锁定后拒绝新的自动排序、手动拖动、重置顺序和改名。
- 锁定不得回放旧快照，也不得把保护文件夹从配置传播中删除。
- 锁定不保存、不复制也不恢复顺序快照；它只保存一个 guard 状态。
- 已排好的顺序和名称在锁定前后完全相同。
- 解锁只恢复操作权限，不补执行锁定期间被拒绝或过期的排序、拖动和编号任务。

## 8. 状态存储规则

以下状态必须分开存储：

1. 自动排序规则和方向。
2. 已保存的手动完整顺序。
3. 排序保护状态。
4. 是否开启拖动后自动编号。
5. 编号批任务及恢复状态。

旧 `manualMode.v1` 只作为迁移输入，不得继续控制业务运行。

## 9. 事件权限表

| 事件 | 可写配置 | 可改可见顺序 | 可写/清手动顺序 | 可改名 |
| --- | --- | --- | --- | --- |
| 明确有效手动放置 | 否 | 是，立即 | 是，写完整顺序 | 仅自动编号已开启时 |
| 用户确认编号预览 | 否 | 不直接改位置 | 否 | 是，仅预览范围 |
| 用户选择新自动规则 | 是 | 仅无手动覆盖时 | 否 | 否 |

## 10. 失败和恢复规则

- NAS 不可用、成员不一致、文件缺失、目标重名、metadata 不一致或任何部分失败都不得显示成功。
- 提交前必须验证 collection ID、item ID、完整成员指纹和目标名称。
- 中断后只能按精确 item ID、当前临时名和备份原名恢复；任意状态不匹配时拒绝猜测。
- 重复执行同一已完成任务必须幂等，不得重复改名。
- 单个文件夹失败必须及时结束并释放执行队列，不能让后续 collection 等待数分钟。
- 一个 collection 的失败、重试、待续任务和提示不得阻塞或冒充另一个 collection 的结果。
- 任一失败都要显示失败数量、首个明确原因和可恢复状态；不能只显示“已完成”。

## 11. 性能规则

- 核心只处理适配器明确提供的当前集合。
- 禁止高频整库轮询、每 500ms 全库扫描或用 2.4 万项“全部”视图作当前集合。
- 排序复杂度为当前集合 `O(n log n)`，手动移动和编号计划为 `O(n)`。
- 放手到可见位置和最终业务名反馈不得出现 10 秒无反馈。
- 后台落盘不得卡住缩略图、右侧预览或 Eagle 其它操作。

## 12. 真实 Eagle 验收层级

真实 Eagle 界面是唯一验收结论。自动测试、日志、内部 ID、指纹和代码审查只能开发排错，不能宣称可用。

### 12.1 单次拖动

- 位置立即正确，下一次在上一次结果上计算。
- 编号与最终可见顺序一致，只改实际受影响的连续区间。
- 缩略图、右侧预览和文件引用始终可用。

### 12.2 连续稳定性

- 同一文件夹真实连续拖动 20 次，包含同一张反复拖、不同照片交替拖、相邻互换、跨行拖动和有/无拍摄时间组合。
- 全过程不得出现临时名、空缩略图、预览消失、“找不到文件”、大进度遮罩或跨文件夹进度。
- 默认手动状态和排序锁定状态下，分别把照片拖到本地测试文件夹；原生文件拖出必须成功，Eagle 内顺序和名称不得改变。

### 12.3 零副作用事件

- 排序锁定关/开各 10 次，顺序、名称和手动顺序始终不变。
- 在 88、169、179 项文件夹之间往返，再刷新、分页和重启，未拖动时改名任务数始终为 0。
- 刷新、文件夹 A/B 往返和重启后，已保存手动顺序不变且不污染其它 collection。

### 12.4 编号结果

- 从左到右、从上到下逐张查看真实卡片名称。
- `1-` 组和 `2-` 组各自从 1 开始连续，无断号、重号、错位或旧名。
- 切换文件夹、刷新和重启后再查看，名称和可见顺序必须完全不变。
- 只有真实界面全部通过后才能请用户验收。

### 12.5 父层与递归范围

- 父层只拖动/编号直属子文件夹，进入叶子层后只拖动/编号直属素材。
- 在四层以上测试树执行每个“应用到全部”，逐层重新进入核对配置，空层和保护层也必须正确。
- 保护层配置已同步，但实际顺序、手动顺序和名称不变；未保护层按明确确认执行。

### 12.6 普通、智能与不可操作上下文

- 同一输入和规则在普通、智能集合得到相同核心顺序。
- 智能集合只处理当前结果，空结果为 0 项，不回退整库。
- “全部”和未知上下文显示受控不可操作；不能读取或处理约 2.4 万项整库数据。

## 13. 代码边界

- 纯排序、范围、手动顺序、保护 guard 和改名计划不得依赖 Eagle DOM、全局 `window`、真实文件系统或 `.library`。
- Eagle DOM 只负责把真实可见顺序适配成 item ID 列表，不得容纳第二套业务规则。
- UI 事件只能调用唯一业务链，不得在 checkbox、计时器、刷新回调或监听器里复制排序与编号逻辑。
- 任何新代码若赋予刷新、切换、启动、时间读取或开关事件以改名权限，就直接违反本文档。
